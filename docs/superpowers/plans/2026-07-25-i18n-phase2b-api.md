# i18n Phase 2b (api 예외 메시지) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NestJS api가 요청 로케일에 맞춰 예외 메시지를 영어(기본)/한국어로 반환한다 (스펙: `docs/superpowers/specs/2026-07-25-i18n-phase2b-api-design.md`).

**Architecture:** 서비스는 `throw new XxxException({ key, args })`로 던지고(상태코드는 예외 클래스가 결정), 전역 `audit-exception.filter.ts`가 요청 `Accept-Language`로 로케일을 해석해 카탈로그에서 번역 후 표준 `{statusCode,message}` 응답을 만든다. 웹은 `dbflow_locale` 쿠키의 앱 로케일을 `Accept-Language`로 전송.

**Tech Stack:** NestJS 10, TypeScript, jest. 새 의존성 없음.

## Global Constraints

- 작업 브랜치: `feat/i18n-phase2b` (main에서 분기; controller가 실행 시점에 브랜치/원장 확인).
- 로케일 `'en' | 'ko'`, 기본 `'en'`, 미지원/미설정 → `'en'`.
- 새 라이브러리 금지(nestjs-i18n 등). 순수 TS 함수 + 기존 필터만 사용.
- 각 태스크 게이트: `pnpm --filter @dbflow/api test` 전체 통과 + 대상 서비스 `grep -n "throw new .*Exception(.*[가-힣]"` 결과 0(주석 제외) + en/ko 카탈로그 키 파리티.
- 예외 메시지 문자열은 **의미 보존**: `ko`는 기존 코드의 한국어 그대로, `en`은 동등 영어(도메인 용어: Change Request, Reviewer, Approver, Apply, Freeze, Rollback, Delegation).
- 스코프 밖(무변경): `crypto/encryption.util.ts` 내부 Error, 감사 로그 저장 요약문, class-validator 메시지.
- `apps/api`만 수정(단 Task 1은 웹 `apps/web/lib/api.ts` 로케일 전송 1개 포함).

- [ ] **Step 3: resolveLocale 구현**

`apps/api/src/i18n/locale.ts`:
```ts
export type Locale = 'en' | 'ko';
export const LOCALES: Locale[] = ['en', 'ko'];
export const DEFAULT_LOCALE: Locale = 'en';

export function resolveLocale(acceptLanguage?: string | null): Locale {
  if (!acceptLanguage) return DEFAULT_LOCALE;
  const primary = acceptLanguage.split(',')[0]?.trim().split('-')[0]?.toLowerCase();
  return (LOCALES as string[]).includes(primary ?? '') ? (primary as Locale) : DEFAULT_LOCALE;
}
```

- [ ] **Step 5: messages 카탈로그 + translate 구현**

`apps/api/src/i18n/messages.ts` (증명용 2개 키로 시작 — 이후 태스크가 확장):
```ts
import type { Locale } from './locale';
import { DEFAULT_LOCALE } from './locale';

type Catalog = Record<string, string>;

const en: Catalog = {
  'changeRequest.notFound': 'Change request not found.',
  'changeRequest.submitRequiresAssignees': 'Submitting requires 1 reviewer and {required} approver(s).',
};

const ko: Catalog = {
  'changeRequest.notFound': '변경요청을 찾을 수 없습니다.',
  'changeRequest.submitRequiresAssignees': '제출하려면 검토자 1명과 결재자 {required}명을 지정해야 합니다.',
};

const MESSAGES: Record<Locale, Catalog> = { en, ko };

export function translate(key: string, locale: Locale, args?: Record<string, string | number>): string {
  const template = MESSAGES[locale]?.[key] ?? MESSAGES[DEFAULT_LOCALE][key] ?? key;
  if (!args) return template;
  return template.replace(/\{(\w+)\}/g, (_, k) => (args[k] !== undefined ? String(args[k]) : `{${k}}`));
}

export { MESSAGES };
```

- [ ] **Step 7: 필터 번역 로직**

`apps/api/src/audit/audit-exception.filter.ts` — import에 `HttpException` 추가, `resolveLocale`/`translate` import. `catch()`의 `super.catch(exception, host);` 직전에:
```ts
    // i18n: {key,args} 페이로드를 요청 로케일로 번역해 표준 메시지로 재구성
    if (exception instanceof HttpException) {
      const res = exception.getResponse();
      if (res && typeof res === 'object' && 'key' in (res as Record<string, unknown>)) {
        const { key, args } = res as { key: string; args?: Record<string, string | number> };
        const locale = resolveLocale(req?.headers?.['accept-language']);
        const translated = new HttpException(translate(key, locale, args), exception.getStatus());
        return super.catch(translated, host);
      }
    }
```
(기존 audit 기록 블록은 그대로 위에 유지.)

### Tasks 2–8: 서비스별 예외 이전

각 태스크는 한 서비스(또는 소그룹)의 한국어 예외를 `{key,args}`로 이전하고, en/ko 카탈로그에 키를 추가하며, 대응 spec의 한국어 message assert를 key/상태 기준으로 갱신한다. 방법·게이트 공통, 대상만 다르다.

**공통 방법 (매 태스크):**
1. 대상 서비스에서 `grep -n "throw new .*Exception" <file>`로 한국어 예외 전수 확인.
2. `apps/api/src/i18n/messages.ts`의 `en`/`ko` 카탈로그에 키 추가(네임스페이스=도메인, key는 영어 slug). `ko`=원문, `en`=동등 영어. 보간은 `{param}` + `args`.
3. 서비스의 각 `throw new XxxException('한국어…')` → `throw new XxxException({ key: '<ns>.<slug>', args? })`. **예외 클래스(상태코드)는 그대로 유지**.
4. 대응 `*.spec.ts`에서 그 메시지를 한국어 정규식으로 assert하던 부분을 key(`/<ns>.<slug>/`) 또는 예외 타입/상태로 갱신.
5. 게이트: `pnpm --filter @dbflow/api test` 통과 + `grep -n "throw new .*Exception(.*[가-힣]" <file>` 0 + `node`로 en/ko 카탈로그 파리티(아래).
6. Commit: `feat(api): i18n <service> exception messages`.

**파리티 체크(매 태스크)**:
```
node -e "const {MESSAGES}=require('./apps/api/dist/src/i18n/messages.js')||{}; " 2>/dev/null || \
node -e "const en=require('./apps/api/src/i18n/messages').?; " 2>/dev/null || echo "ts-node 필요"
```
(ts 소스라 런타임 require 불가 시: 카탈로그 en/ko는 같은 객체 리터럴에 나란히 두므로, 리뷰 시 키 누락은 `pnpm --filter @dbflow/api exec tsc --noEmit` + 육안. 각 태스크는 en/ko 양쪽에 동일 키를 추가하는 것을 규약으로 한다.)
