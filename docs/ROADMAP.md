## 🧭 기능 오케스트레이션 (실행 계획)

아래 Tier-2 후보 문서와 UX 후보 문서를 **경쟁 제품 조사(공통 기본기 / 차별화 기회)와 합쳐 하나의 실행 계획으로 묶은 것**:
**[feature-orchestration.html](./feature-orchestration.html)** (2026-07-29).

세 축(따라잡기 · 심화 · 앞서가기)으로 분류하고, 실행 순서와 **일부러 만들지 않을 것** 목록까지 담았다.
HTML이므로 GitHub에서는 소스로만 보인다 — 브라우저로 파일을 직접 열거나, 발행된 페이지를 볼 것.

핵심 결론 3가지:
- **첫 데모 탈락 사유 5개**: 통제된 조회 경로 · 자동화 API/토큰 · 대상 DB별 변경 이력 · 온라인 DDL(gh-ost) · 취소/철회+재시도
- **가치/비용 최고**: 드리프트 감지 — 이미 가진 스키마 diff + 대상 DB 레지스트리를 스케줄링하면 된다
- **차별화 wedge**: 경쟁사 무료·저가 티어는 감사 로그가 없거나 보존 7일인데 감사인은 12~18개월을 요구한다 → **감사 증적 팩**이 1순위 베팅

각 항목은 개발 사이클(brainstorm→스펙 검수→plan→plan 검수→구현→리뷰→머지)로 진행.

### 1단계 — 결재 인박스 슬라이스 (전부 S, 기존 테이블 쿼리만으로 가능)

- [ ] **E3. 재검토 요청 버튼** — 반려 후 수정 → 검토자 decision 리셋 + 재알림
- [ ] **E8. 위임 중 표시** — 결재자 칩 "위임 중" 배지, 대결자 인박스 라우팅 표면화
