# DBFlow 기능 체크리스트 (수동 QA)

현재 구현된 기능을 직접 클릭하며 확인하기 위한 목록입니다. 각 항목을 눌러보고 `[ ]` → `[x]`로 체크하세요.
**이 문서는 기능이 완성될 때마다 최신화합니다.** (최종 업데이트: 2026-07-19 — 지정 검토/결재·프로필·관리자·감사 로그·SQL 리뷰 정책 반영)

## 실행 & 로그인

- 기동: `./start.sh` (종료 `./stop.sh`, DB까지 `./stop.sh --all`)
- Web: http://localhost:3000 · API: http://localhost:3001
- seed 계정 (비밀번호 모두 `password1234`):

| 역할 | 이메일 | 이름/부서 | 주요 권한 |
|---|---|---|---|
| 개발자 (DEVELOPER) | `dev@dbflow.io` | 개발자 / 개발팀 | 변경요청 생성/제출, 스키마 Diff |
| 검토자 (REVIEWER) | `dba@dbflow.io` | 검토자 / DBA팀 | 지정된 요청 1차 검토 승인/반려 |
| 결재자 (APPROVER) | `approver@dbflow.io` | 결재자 / 인프라팀 | 지정된 요청 최종 결재, 대상 DB 관리, 적용 |
| 관리자 (ADMIN) | `admin@dbflow.io` | 관리자 / 운영팀 | 계정 생성·관리, 감사 로그, 지정자 재지정 |

## 1. 인증 / 공통 셸 / 테마

- [ ] 로그인: `dev@dbflow.io` / `password1234` → 대시보드 이동
- [ ] 로그인 실패: 틀린 비밀번호(8자 이상) → 401 에러 메시지
- [ ] 미로그인 상태로 `/dashboard` 직접 접근 → `/login`으로 리다이렉트
- [ ] 로그아웃(사이드바 하단) → 로그인 화면으로
- [ ] 사이드바 하단에 `이름 | 부서` / `역할` 2줄 표시 (예: `검토자 | DBA팀` / `검토자(DBA)`)
- [ ] 사이드바 네비: 활성 메뉴 하이라이트
- [ ] **데스크톱 사이드바 접기/펴기**(상단 토글): 접으면 아이콘 레일(라벨→툴팁) + 본문 넓어짐, 새로고침 후 상태 유지(localStorage). 접힘 시 하단 테마·로그아웃은 숨김(펴면 노출)
- [ ] 모바일 폭: 사이드바가 햄버거 → 드로어로 접힘(풀 라벨, 접기 토글 없음), 링크 클릭 시 자동 닫힘, Esc로 닫힘
- [ ] **테마 토글**(사이드바 하단): 라이트 / 다크 / 시스템 3-상태 전환
- [ ] 다크 선택 후 **새로고침** → 다크 유지 (FOUC 없이)
- [ ] 시스템 선택 → OS 다크모드 설정 따라감

## 2. 역할별 접근 제어 (사이드바 메뉴 노출)

- [ ] 개발자: 대시보드 / 변경요청 / 스키마 Diff (대상 DB·사용자관리·감사 숨김)
- [ ] 검토자: 대시보드 / 변경요청 (스키마 Diff·대상 DB 숨김)
- [ ] 결재자: 대시보드 / 변경요청 / 스키마 Diff / 대상 DB
- [ ] 관리자: **사용자 관리 / 감사 로그** (로그인 시 `/users`로 이동, 대시보드 카드 없음)
- [ ] 권한 없는 URL 직접 접근 → "접근 불가" 안내 카드

## 3. 대시보드 (지정 기반, 역할별로 다름)

- [ ] 개발자: 내 작성 중 / 내 진행 중 / 내 반려 / 내 완료 (내가 쓴 것)
- [ ] 검토자: 검토 대기 / 결재 대기 / 반려 / 완료 (**나에게 지정된** 것)
- [ ] 결재자: 검토 진행 / 결재 대기 / 반려 / 완료 (**나에게 지정된** 것) — "결재 대기"는 내가 아직 결재 안 한 것만(`myApprovalPending`), 내가 이미 승인한 부분승인 CR은 제외
- [ ] 현재 역할의 "대기" 카드가 강조(primary)됨
- [ ] KPI 카드 클릭 → 해당 필터가 걸린 변경요청 목록(`?filter=`)
- [ ] 최근 변경요청 테이블(최신 6건), 행 클릭 → 상세, "전체 보기" → 목록

## 4. 변경요청 워크플로우 (순서대로 한 바퀴 권장)

### 4-1. 목록
- [ ] 목록 테이블(제목/환경/상태/작성자/생성일), 행 클릭 → 상세
- [ ] 상태 필터 탭(전체/검토대기/결재대기/반려/완료) — 모든 역할 공통 노출
- [ ] 자기에게 지정/작성된 요청만 목록에 보임 (지정 기반 가시성)
- [ ] 모바일 폭에서 테이블 → 카드 스택 전환

### 4-2. 생성 (개발자)
- [ ] "새 변경 요청" → 제목/설명/대상환경(DEV·STAGING·PROD)
- [ ] **검토자 지정 드롭다운**(이름·부서 표시)
- [ ] **결재자 지정 — 대상환경 정책(`requiredApprovals`)만큼 N개 셀렉트** 렌더, 환경 변경 시 N 재계산, 같은 결재자 중복 선택 방지
- [ ] SQL 파일 여러 개 추가/삭제, 각 파일 유형(DDL/DML) 지정
- [ ] 필수값·지정자(N명 전원) 누락 시 검증 에러
- [ ] 생성 성공 → 상세 이동

### 4-3. 상세 & 제출 (개발자)
- [ ] 상세: 제목·환경·작성자·상태 + **지정 검토자/결재자** 표시
- [ ] 설명 + SQL 파일(코드 블록) + 상태 히스토리 타임라인
- [ ] 2-컬럼 레이아웃(데스크톱)
- [ ] "검토자에게 제출" → SUBMITTED (검토자 1명 + 정책 수만큼 결재자 없으면 제출 불가, 결재자 미달 시 400)
- [ ] **재지정**: DRAFT는 작성자, 제출 후는 관리자만 검토자/결재자 변경 가능
- [ ] **재지정 인원 게이트**: 제출 후 관리자가 결재자를 정책 수와 다르게(예: 정책 2명인데 1명) 재지정 시 400 차단 (정책 미달로 최종승인 방지)

### 4-4. 검토 (지정된 검토자만)
- [ ] 지정 검토자만 검토 승인/반려 가능 (미지정자는 403 + 목록에 안 보임)
- [ ] 승인 → REVIEW_APPROVED, 반려 → REVIEW_REJECTED (+ 코멘트)

### 4-5. 최종 결재 (지정된 결재자들 — 다중 결재자 만장일치)
- [ ] 지정 결재자만 결재 가능(미지정자 403), 이미 결재한 사람 재결재 409
- [ ] 상세에 **결재자별 상태 뱃지(승인/반려/대기)** + 진행률(`approved/total`)
- [ ] N명 중 일부만 승인 → 상태 `REVIEW_APPROVED` 유지(부분 승인)
- [ ] **N명 전원 승인 시에만** → FINAL_APPROVED
- [ ] 1명이라도 **반려** → 즉시 FINAL_REJECTED (나머지 대기 무효)
- [ ] 동시 결재(마지막 2명 동시 승인)에도 최종 전이 1회만 발생(행 잠금)

### 4-6. 적용 (결재자)
- [ ] **린트 검사**(INFO/WARN/BLOCK) · 대상 DB 선택 · **Dry-run 미리보기**
- [ ] **적용** → 대상 DB 반영, 성공/실패 배너, 상태 APPLIED

### 4-7. 적용 이력 & 롤백
- [ ] 적용 이력(실행 상태·단계별 결과) · 백업 상태
- [ ] **롤백** 실행 → 이전 상태로

## 5. 스키마 Diff 생성기 (개발자 / 결재자)

- [ ] 대상 DB 선택 + 기준 스키마 DDL 입력 → "Diff 미리보기"
- [ ] 차이 목록(테이블/컬럼/인덱스) · 파괴적 변경 경고 · 차이 없음 안내
- [ ] (개발자) "변경요청으로 생성"

## 6. 대상 데이터베이스 관리 (결재자)

- [ ] 목록 · "새 대상 DB" 등록(이름/환경/종류/호스트/포트/사용자/비밀번호/DB명) · 입력 검증
- [ ] **연결 테스트**(성공: 서버버전·지연시간 / 실패: 사유)
- [ ] 수정(비밀번호는 입력 시에만) · 삭제(확인 후)

## 7. 사용자 관리 (관리자)

- [ ] `/users` — 관리자만 접근(그 외 "접근 불가"), 비-ADMIN `GET /users/admin` 403
- [ ] 계정 생성: 이메일 / 이름 / **부서** / 역할(개발자·검토자·결재자·관리자) / 초기 비밀번호
- [ ] 비밀번호 8자 미만 등 검증 에러
- [ ] **목록에 전 역할 표시**(개발자·관리자 포함 — 기존 검토/결재자만 보이던 버그 해소), 이름·**이메일**·부서·역할·가입일
- [ ] **역할 필터**(전체/4역할) + **이름·이메일 검색**(디바운스) · 변경 시 1페이지로 리셋
- [ ] **서버 페이지네이션**(20/페이지): 총 건수·이전/다음, 페이지 2+에서 검색해도 stale 결과 안 뜸
- [ ] 생성 후 현재 필터·페이지로 목록 갱신

## 8. 감사 로그 (관리자)

- [ ] `/audit` — 관리자만 접근
- [ ] 이벤트 기록: 로그인 성공/실패, 권한 거부(403), 사용자 생성/프로필수정, CR 생성·제출·검토·결재·지정변경, 적용·롤백, 대상DB 생성·수정·삭제, **결재 정책 변경(`APPROVAL_POLICY_UPDATED`)**
- [ ] 필터: 액션(`APPROVAL_POLICY_UPDATED` 포함) / 대상유형(`APPROVAL_POLICY` 포함) / 결과(성공·실패) / 기간(from~to) / 행위자 ID · 페이지네이션
- [ ] 행 클릭 → 메타데이터 펼침 · 결과 뱃지(성공=emerald, 실패=red)
- [ ] **CSV / JSON 내보내기**(인증 필요)
- [ ] 대상DB 비밀번호·SQL 본문이 로그에 없음
- [ ] **변조 불가**: DB에서 `UPDATE/DELETE audit_log` 시도 → 트리거가 차단(`append-only`)

## 9. SQL 리뷰 정책 (관리자)

- [ ] `/sql-review` — 관리자만 접근(그 외 "접근 불가")
- [ ] 규칙 × 환경(DEV/STAGING/PROD) 그리드 — 각 셀 수준 드롭다운(DISABLED/INFO/WARN/BLOCK)
- [ ] 기본값(무회귀): DEV는 위험규칙 `WARN`(강등), STAGING/PROD는 `BLOCK`, DROP_INDEX는 `INFO`
- [ ] 수준 변경 저장(낙관적 반영, 실패 시 되돌림)
- [ ] **정책 반영**: DEV의 `TRUNCATE`를 `BLOCK`으로 올리면 → 해당 DEV CR의 lint 미리보기/적용에서 BLOCK 차단
- [ ] `DISABLED`로 변경 → 해당 규칙이 lint에 표시되지 않음
- [ ] 정책 변경이 감사 로그에 `SQL_POLICY_UPDATED`(from→to)로 남고 감사 필터로 조회됨
- [ ] `--seed` 없이 재기동해도 정책 21행 유지(데이터 마이그레이션)

## 10. 결재 정책 (관리자) — 환경별 결재 인원

- [ ] `/approval-policy` — 관리자만 접근(그 외 "접근 불가")
- [ ] 환경(DEV/STAGING/PROD) × 필요 결재자 수 셀렉트(1~5) — 변경 시 낙관적 반영, 실패 시 되돌림
- [ ] 기본값(무회귀): 전 환경 `1`명 (기존 단일 결재자 흐름과 동일하게 동작)
- [ ] **정책 반영**: PROD를 `2`로 올리면 → 이후 PROD 대상 CR은 결재자 2명 지정·제출 필요, 2명 전원 승인해야 최종 승인
- [ ] 정책 변경이 감사 로그에 `APPROVAL_POLICY_UPDATED`(env, from→to)로 남고 감사 필터로 조회됨
- [ ] 개발자/검토자/결재자의 PATCH 시도 → 403 (조회 GET은 로그인 사용자 공통 — 생성 폼용)
- [ ] `--seed` 없이 재기동해도 `approval_policy` 3행 유지(데이터 마이그레이션)

## 11. 작업창 · 동결 (관리자)

- [ ] `/apply-schedule` — 관리자만 접근(그 외 "접근 불가"), 서버 타임존이 Asia/Seoul 아니면 경고 배너
- [ ] 작업창 추가(환경/요일/시작~종료) · 삭제 — 종료 00:00 입력은 24:00(자정)으로 표시
- [ ] 동결 등록(환경/기간 KST/사유) · 해제 — 과거 동결은 목록에 안 보임(의도)
- [ ] **게이트**: 창이 정의된 환경은 창 밖 적용 409 + "다음 작업창" 안내, 창 안 적용 성공
- [ ] **동결 우선**: 창 안이라도 동결 중이면 409 + 사유 노출, 해제 후 적용 성공
- [ ] **무회귀**: 창 없는 환경(기본 DEV)은 항상 적용 가능
- [ ] 동결 중에도 롤백은 정상 동작(게이트 비대상)
- [ ] CR 상세 적용 패널에 배너 3종(적용 가능/작업창 아님+다음 창/동결 중+사유) + 버튼 비활성
- [ ] 창/동결 변경이 감사 로그(`APPLY_WINDOW_UPDATED`/`FREEZE_UPDATED`)에 남고 필터로 조회됨
- [ ] 비ADMIN: 창/동결 POST·DELETE 403, 조회(GET)는 로그인 공통 200

## 12. 부재 위임 (검토자/결재자)

- [ ] `/delegations` — 검토자·결재자·관리자 접근(그 외 "접근 불가")
- [ ] 본인 부재 위임 등록(대리인=같은 역할, 기간 KST, 사유) · 해제
- [ ] ADMIN은 타인 위임 등록 가능, 비-ADMIN은 본인만(요청 delegatorId 무시)
- [ ] 역할 다른 대리인/자기위임/기간 역전 → 검증 에러(400)
- [ ] **대리 결재**: 위임 기간 중 대리인이 위임자 지정 CR을 결재 → 슬롯 채워지고 "Y (X 대리)" 표기, 진행률 정상, 최종 승인 도달
- [ ] **대리 검토**: 대리인이 검토 승인/반려, 감사에 onBehalfOf 기록
- [ ] **가시성**: 대리인 목록/상세에 위임 CR이 보이고, 대시보드 "결재 대기"에 대리 대기 반영(myApprovalPending)
- [ ] 기간 밖에는 대리 불가(403), 위임이 지정 인원·역할 게이트 우회 안 함
- [ ] 위임 등록/해제가 감사(`DELEGATION_UPDATED`)에 남고 필터로 조회 · DELETE는 위임자/ADMIN만(타인 403)
- [ ] 위임 0건이면 기존 검토/결재 동작 그대로(무회귀, 직접 결재는 decidedBy 없음)
- [ ] **직무분리(SoD)**: 한 사람은 한 CR에서 결재 1건만(직접+대리 합산) — P1이 X 슬롯(대리) 결재 후 같은 CR의 Y 슬롯 시도 → 409, 상세에서 대리/직접 버튼 안 보임(`iAlreadyActed`)

## 추천 시나리오 — 전체 흐름 한 바퀴

1. **관리자**(`admin@dbflow.io`) → 필요 계정 생성 확인 · **결재 정책 PROD=2 설정** · 감사 로그 열기
2. **결재자** → 대상 DB 등록 + 연결 테스트
3. **개발자** → PROD 변경요청 생성(검토자 1명 + **결재자 2명 지정**) → 제출
4. **검토자** → (지정된 요청) 검토 승인
5. **결재자 A** → 최종 승인(진행 1/2, 상태 유지) → **결재자 B** → 최종 승인(2/2 → FINAL_APPROVED)
6. **결재자** → 린트 → Dry-run → 적용 → 이력
7. **관리자** → 감사 로그에서 위 모든 이벤트(+정책 변경) 확인 + CSV 내보내기
8. 각 단계마다 대시보드 KPI 변화 + 테마 토글 점검
