# DBFlow 다음 기능 후보 (Tier-2) — 경쟁·유사 툴 리서치 기반

> 작성 2026-07-19. Tier-1(감사 로그 · SQL 리뷰 정책 · 커스텀 승인 플로우) 완료 후,
> 다음에 구현할 기능을 유사 툴 조사로 도출한 후보 목록. 확정 스펙이 아니라 **선택지 카탈로그**다.
> 각 항목은 실제 구현 전 개발 사이클(brainstorm→스펙 검수→plan→plan 검수→구현→리뷰→머지)로 확정한다.

## 포지셔닝 재확인 (선정 필터)

DBFlow는 **통제된 절차**가 핵심 가치인, 규제 조직(금융·공공·대기업)용 DB 변경 형상관리 도구다.
Flyway식 자동 마이그레이션이 아니다. 따라서 후보는 아래 기준으로 걸렀다.

- ✅ **채택**: 사람 검수·결재·감사 추적을 **더 강하게/편하게** 만드는 기능
- ❌ **탈락(안티-비전)**: 사람 검수를 건너뛰거나 절차를 생략하는 자동화
  (예: git commit→자동 이슈 생성, 선언형 desired-state 자동 DDL 반영, 승인 없는 자동 롤아웃)

**현재 보유 기능**(중복 제안 방지 기준): 역할 접근제어 · 역할별 대시보드 · CR 워크플로우(생성→제출→검토→다중결재→적용→롤백) · 스키마 Diff · 대상 DB 관리+연결테스트 · 사용자 관리 · append-only 감사 로그(+CSV/JSON 내보내기) · SQL 리뷰 정책(환경×규칙 심각도) · 결재 정책(환경별 N명 만장일치) · 텔레그램 알림 · 프로필.

---

## 후보 카탈로그

규모 표기: **S**(1~2일) / **M**(3~5일) / **L**(1~2주+). 규모는 대략치.

### A. 승인 거버넌스 심화 — "누가/어떻게 결재하나"를 정교하게

| # | 기능 | 설명 | 비전 적합성 | 참고 툴 | 규모 |
|---|------|------|------------|---------|------|
| A1 | **결재 위임 · 에스컬레이션 · OOO** | 결재자 부재 시 대결자 지정(✅ **부재 위임 완료 PR #14**), 기한 초과 시 자동 에스컬레이션·SLA 리마인더(⏳ 후속 — 스케줄러·알림 발송 인프라 필요) | ★★★ "결재 병목" 해소 — 감사 단골 항목 | ITIL/ServiceNow | M |
| A2 | **위험도 기반 결재 라우팅 (Risk Center)** | SQL 종류 × 환경 × 대상 테이블 크기로 **위험도 자동 산정** → 위험도별로 필요 결재자 수/결재 체인 자동 선택 | ★★★ 현재 "환경별 N명" 평면 정책을 조건 기반으로 승격. SQL 리뷰 정책과 자연 결합 | Bytebase Risk Center, ITIL 위험 매트릭스 | L |
| A3 | **긴급 변경 fast-path + 사후 검토(PIR)** | P1 장애용 신속 경로: 축약 결재로 먼저 적용 → **사후 필수 검토(Post-Implementation Review)** 기록 강제 | ★★★ 현실(긴급 상황)을 인정하되 감사 추적은 유지 — 통제 도구의 차별점 | ITIL 3-tier(표준/일반/긴급) | M |
| A4 | **정족수(N-of-M) 결재** | 현재 "지정 N명 전원 승인"에 더해 "DBA 그룹 중 아무 2명" 같은 그룹·정족수 승인 옵션 | ★★ 기존 만장일치 모델의 증분 확장 | ITIL(ServiceNow는 OOTB 취약, 우리가 앞섬) | M |
| A5 | **결재 시 전자서명/재인증 (non-repudiation)** | 최종 결재 순간 비밀번호/OTP 재인증을 요구해 부인방지 확보(단순 클릭 → 서명) | ★★★ 금융·의료 규제(예: 21 CFR Part 11) 대응 | 21 CFR Part 11 | S~M |

### B. 시점·안전 통제 — "언제/무엇이" 적용되나

| # | 기능 | 설명 | 비전 적합성 | 참고 툴 | 규모 |
|---|------|------|------------|---------|------|
| B1 | **변경 작업창 · 동결 기간** ✅ **완료 (PR #13)** | 승인된 변경을 **승인된 작업창** 안에서만 적용, 분기말·감사·피크 기간 **동결(freeze/blackout)** 설정. (예약 자동 실행은 후속 확장으로 분리) | ★★★ 금융·공공 필수 | ITIL 변경 캘린더, Archery, Bytebase | M~L |
| B2 | **롤백 계획 필수화 + 역 SQL 자동생성** | 제출 시 롤백 SQL/계획 첨부를 강제하고 **검토·결재자가 롤백안을 보고 승인**. 가능한 경우 역 SQL 자동 생성 | ★★★ 기존 백업+롤백 메커니즘을 "결재 시점의 검토 가능한 산출물"로 승격 | ITIL back-out plan, Yearning/Archery 롤백 SQL 자동생성 | M |
| B3 | **드리프트 감지 (out-of-band 변경 탐지)** | 적용 직전 대상 DB를 최종 승인 스냅샷과 비교 → 절차 밖에서 직접 바뀐 부분을 리포트/차단 | ★★★ "통제 절차" 포지셔닝의 실질 공백(누군가 prod 직접 수정) | Redgate Flyway Enterprise | L |
| B4 | **승인 산출물 무결성(리뷰↔적용 동일성 보장)** | 승인된 SQL과 실제 적용 SQL이 **바이트 동일**함을 보장, 승인 후 편집 차단 | ★★★ 감사 신뢰의 근간. 현재 구현 강도 점검 후 하드닝 | Redgate check/deploy 분리 게이트 | S~M |
| B5 | **락 위험 / 대형 테이블 DDL 규칙** | SQL 리뷰에 "임계 크기 초과 테이블 DDL = 장시간 락 위험" 등 테이블 크기 인지 규칙 추가 | ★★ 기존 SQL 리뷰 정책의 저비용 증분 | Bytebase 대형테이블 DDL 규칙 | S |

|---|------|------|------------|---------|------|

1. **A1 잔여 — 에스컬레이션 · SLA 리마인더 (+ 알림 발송 인프라 D1)** 🥇
   부재 위임은 완료됐으나, 기한 초과 자동 에스컬레이션·SLA 리마인더는 **스케줄러(@nestjs/schedule) + 실제 알림 발송 채널**이 선행돼야 함(현재 telegramChatId는 저장만, 발송 코드 없음). D1(이메일/Slack/웹훅/인터랙티브 결재)과 함께 묶는 슬라이스.

2. **A3 — 긴급 변경 fast-path + 사후 검토(PIR)** 🥈
   경쟁 툴 대비 **차별적 통제 가치**. "긴급 상황에도 절차를 버리지 않고, 사후 검수로 감사 추적을 메운다". B2(롤백안)와 결합 시 긴급 변경 안전망 완성. **B1의 동결 긴급 우회가 여기로 이관됨**.

3. **B2 — 롤백 계획 필수화 + 역 SQL 자동생성** 🥉
   제출 시 롤백안을 강제해 결재자가 보고 승인. 기존 백업+롤백을 "결재 시점 산출물"로 승격.

> 대안: **A2(위험도 기반 라우팅)** — 더 야심찬 방향이나 규모(L)가 크다. / **부재 위임 SoD 옵션 가드**(최종 리뷰 Minor#1) — 규제 SoD 필요 시 소규모 후속.

## 의도적으로 하지 않는 것 (안티-비전)

- git commit 기반 **자동 이슈 생성** / 선언형 **desired-state 자동 DDL 반영** — 사람이 특정 변경을 의도적으로 작성·제출하는 행위를 약화시킴 (Bytebase GitOps/declarative의 해당 부분).
- 승인 없는 **자동 롤아웃** / 절차 생략 옵션 — 제품 비전과 정면 충돌, 기본값으로 절대 제공하지 않음.
